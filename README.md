## 1. Что за проект

`NSSP-Fetch` - набор Python-скриптов для загрузки и обработки данных
CDC NSSP Emergency Department Visit Trajectories.

Проект позволяет загрузить исходный CSV-файл с данными CDC, отфильтровать
его по штату Техас и отдельно получить данные за 2024 год. Результаты
сохраняются в формате CSV и могут использоваться для дальнейшего анализа
или визуализации в Tableau.

Также в проекте есть отдельный скрипт для отладки и небольшого
исследовательского анализа данных.

Основные технологии проекта - Python, pandas, requests, NumPy,
scikit-learn, SciPy и Matplotlib. Для получения данных используются
внешние источники CDC/Socrata и COVIDcast API.

## 3. Что уже есть

* [`README.md`](https://github.com/malonekt/NSSP-Fetch/blob/main/README.md) —
  описание проекта, назначение основных скриптов, требования,
  команды запуска, описание выходных файлов и краткий раздел
  по устранению ошибок
* `nssp_fetch_state_tx.py` - скрипт загрузки исходного CSV-файла
  с данными CDC/Socrata
* `filter_nssp_tx.py` - скрипт фильтрации данных по Техасу и
  выделения данных за 2024 год
* `nssp_fetch_and_analysis.py` - скрипт для тестирования, отладки
  и небольшого анализа данных
* `.gitattributes` - файл настроек Git
* Описана директория `outputs/`, в которую после запуска скриптов
  сохраняются исходные и обработанные CSV-файлы, а также возможные
  графики
* В README указаны используемые библиотеки: `pandas`, `requests`,
  `numpy`, `scikit-learn`, `scipy`, `matplotlib`
* Описан источник данных: CDC NSSP Emergency Department Visit
  Trajectories, Socrata dataset `rdmq-nq56`
* В README приведена ссылка на Tableau Dashboard для визуализации
  обработанных данных.

Отдельной папки `docs/` в репозитории нет. Также отдельного файла
`requirements.txt` в текущей структуре репозитория нет - зависимости
перечислены непосредственно в README.

## 4. Чего не хватает

Вопросы, на которые не удалось найти полного ответа в существующем
README и структуре проекта:

1. **Подробная установка проекта с нуля.** Указано, что требуется
   Python 3.8+ и pip, а также приведена команда установки библиотек.
   Однако нет пошаговой инструкции по созданию виртуального окружения,
   его активации и проверке установленной версии Python.

2. **Чёткая структура рабочего процесса.** В README перечислены команды
   запуска, но не очень подробно объясняется весь процесс:
   загрузка данных → сохранение исходного CSV → фильтрация → получение
   очищенного файла → дальнейший анализ или Tableau.

3. **Подробное описание источников данных.** Указано, что используется
   CDC/Socrata dataset `rdmq-nq56`, а в исходном коде также используется
   COVIDcast API. Не описано, в каких случаях используется каждый источник
   и чем отличаются получаемые данные.

4. **Описание структуры данных.** Не приведён полный список столбцов
   исходного CSV и не объясняется назначение основных полей, например
   географических идентификаторов, дат, показателей посещений и FIPS.

5. **Описание фильтрации по Техасу.** README говорит о фильтрации данных
   до Texas, но подробно не объясняет используемую логику. В коде штат
   определяется, в частности, по FIPS, начинающимся с `48`, а также
   по значениям географических полей.

6. **Описание фильтрации по 2024 году.** Не объясняется, какое именно
   поле используется для определения даты и как формируется выборка
   за 2024 год.

7. **Описание очистки данных.** В проекте присутствует дополнительная
   логика удаления отдельных столбцов и формирования очищенных CSV,
   однако в README эта часть описана недостаточно подробно. Например,
   `filter_nssp_tx.py` удаляет ряд технических и вспомогательных полей
   и создаёт файлы `nssp_tx_all_years_clean.csv` и
   `nssp_tx_2024_clean.csv`.

8. **Описание `nssp_fetch_and_analysis.py`.** README называет его
   debugger/analysis runner, но не описывает подробно, какие именно
   аналитические операции выполняются. В коде используются, среди
   прочего, KMeans, `zscore` и Matplotlib.

9. **Описание выходных файлов.** Перечень основных файлов есть,
   но не хватает таблицы с объяснением, для чего нужен каждый CSV,
   чем отличается raw-файл от filtered и clean-версий и какой из них
   рекомендуется использовать для Tableau.

10. **Обработка ошибок и проблем с API.** README содержит несколько
    кратких подсказок, например про `ModuleNotFoundError` и отсутствие
    county-level данных. Однако нет полноценного раздела с типовыми
    ошибками при загрузке данных, проблемами сети, изменением структуры
    ответа API и способами их диагностики.

11. **Настройка Tableau.** Есть ссылка на готовый Dashboard и указание
    использовать `nssp_tx_all_years.csv` или `nssp_tx_2024.csv`, однако
    нет пошаговой инструкции по подключению CSV к Tableau, настройке
    географии и использованию FIPS5 для карт.

12. **Структура проекта.** Нет отдельного документа, который объясняет
    назначение каждого Python-файла и зависимости между скриптами.
    Разработчику приходится изучать исходный код, чтобы понять,
    какие функции относятся к загрузке, фильтрации и анализу.

13. **Файл зависимостей.** В README приведён список библиотек и пример
    `requirements.txt`, но самого `requirements.txt` в репозитории нет.
    Из-за этого зависимости не закреплены в отдельном файле, что
    усложняет воспроизводимую установку проекта.

14. **Лицензия.** В README указано `MIT-style`, однако отдельного
    файла `LICENSE` среди файлов репозитория не видно. Поэтому условия
    использования и распространения проекта стоит оформить отдельным
    файлом лицензии.

> Часть технических деталей удалось уточнить по исходному коду, однако
> они не отражены в существующей документации. Для полноценной
> документации проекта желательно отдельно описать структуру данных,
> источники API, последовательность обработки, формат выходных файлов
> и подключение результатов к Tableau.
